# ADR-004 — numerical correctness and experimental acceptance gates

**Status:** **APPROVED by project maintainer on 2026-10-24** as prospective research/regression criteria and measurement policy. Prepared and approved **after** the locked official MNIST test was measured. Approval does **not** retrospectively pre-register the 2026-10-24 accuracy result, prove hardware efficiency, establish a general-purpose release threshold, or authorize merging PR #9 to `master`. Implementations remain subject to the approved integer training boundary (ADR-002) and independent correctness gates.

**Related:** [issue #10](https://github.com/philsupertramp/integers/issues/10), [issue #15](https://github.com/philsupertramp/integers/issues/15), [draft PR #34](https://github.com/philsupertramp/integers/pull/34), [frozen evaluation protocol](MNIST_FINAL_PROTOCOL.md), [original official MNIST test reports](../reports/held_out/mnist/full/2026-10-24-locked-fa405dee/README.md).

## Measured evidence (factual; not a proposed threshold)

On x86_64 Manjaro, Rust 1.95.0, 20 epochs, 55k training/5k validation, one final official 10k-image MNIST test per backend/seed at commit `fa405dee`, batch 32, `lr_shift=7`, dense MLP `784→128→128→10`, seeds 1337/2027/4242:

| Measurement | Integer | Independent scalar FP32 |
|---|---:|---:|
| Official test mean accuracy | **95.41%** | **96.87%** |
| Three-model seed range | 95.23–95.67% | 96.78–96.97% |
| Mean wall time per trained model | **1387.95 s** | **341.14 s** |
| Mean peak whole-process RSS | **434.06 MiB** | **434.10 MiB** |

The observed mean gap is **1.45 percentage points**; integer runtime is **4.07×** this deliberately scalar, **unoptimized** FP32 reference on the measurement machine. The same 10k official examples were used for all three seeds; they do **not** represent 30k independent test examples. All 20-epoch validation matrices conserve class counts and show zero recorded nonfinite/extreme outputs. These facts support **one reference dense workload**, not broad architectural performance or all-layers compliance.

## Approved acceptance hierarchy

### A. Required correctness and runtime-boundary gates (hard, but limited in scope)

1. `cargo test --locked` for dyadic regression, independent layer/gradient oracles, public API smoke, Iris validation and existing benchmark protocol CI must pass on the candidate. Assertions for scale alignment, rounding, saturation, clipping/STE masks, and batch-mean gradients retain their independent expected tolerances. **Do not invent a global absolute floating-point error epsilon for arbitrary dyadic operations.**
2. For the declared **integer-compliant** runtime path, forward, backward, and optimizer updates must not execute floating-point arithmetic. Preparation, independent FP32 reference and reporting are exempt under approved ADR-002. Experimental FP64 **BatchNorm/Softmax remain noncompliant** and must be disabled, explicitly segregated or fixed under issue #26 before any library-wide integer-only claim.
3. Reproducible experiment metadata (data hashes, code commit, Rust version, seeds, sample counts, batch/optimizer, time/RSS), honest split separation and no test-driven selection must be present. No missing or silently replaced seeds.
4. For the *measured workload*, zero recorded non-finite/excessively-clipped output counters and no unhandled arithmetic overflow. (Existing counters are useful but not proofs for uninstrumented arithmetic.)

### B. Approved **prospective** dense-MNIST regression gate

For a *future fixed-version* integer-dyadic dense MLP training benchmark, with the same frozen data source and architecture, full 20-epoch budget and **at least three predeclared model seeds**:

- **Mean official test accuracy ≥94.0%.**
- **Worst seeded model accuracy ≥94.0%.**
- **Integer mean accuracy within ≤2.0 percentage points of the matched scalar FP32 baseline**, with identical seed schedule, model and data order.
- Report per-seed and mean curves, range, numeric anomaly counts, time and whole-process peak RSS. Report any failure, do not drop outlier seeds.

**Methodological limitation:** These **approved** tolerances were *informed by* the above observed test results. They are project **regression targets for subsequent implementations**, but they cannot establish that the 2026-10-24 experiment satisfied a genuinely pre-registered statistical performance hypothesis. The original MNIST test is now *seen*; a fresh independent workload/data reservation is needed if a later change is optimized in response to its score and seeks a fresh generalization claim.

### C. Hardware and performance gates — report-only now, hard limits later

- Record wall time, CPU/architecture, compiler/build settings, memory, source-data residency and implementation maturity for x86_64 and later Pi 5. For the present evidence, **4.07× slower** and about **434 MiB** RSS are *descriptive baselines* only.
- **Do not impose a portable hard runtime or RSS percentage gate yet.** The FP32 implementation is intentionally scalar, the current RSS includes all in-memory datasets, and there has been no controlled AArch64 Pi 5 resource study. In particular, these numbers cannot support a claim of integer instruction efficiency, power saving or deployability on Pi 5.
- An optional *machine-local regression budget* (e.g. within a modest fixed factor of the current baseline when hardware/build/data are truly identical) can be defined later. It must not be mistaken for product viability or edge suitability.
- Future AArch64/NEON and Pi 5 comparison (issues #17/#18) should establish hardware-specific throughput, memory and energy targets from **new controlled measurements**, not assumptions.

### D. Release versus research milestone — distinct decisions

Passing a single dense-MNIST learning gate means **the integer research prototype learned a substantial workload**. It does **not** automatically authorize PR #9 `big-refactor → master`, publish a package, or claim the entire public API is integer-only. Such decisions also need #26 runtime float audit, correctness coverage appropriate to the exposed API, #19 license/API approval, #16 precision choices where needed, and the maintainer's explicit integration authorization.

## Approval and follow-up

The project maintainer approved the proposed future MNIST regression thresholds (**integer mean ≥94.0%, all three seeded models ≥94.0%, and a ≤2.0 percentage-point deficit versus the paired scalar FP32 mean**), plus required correctness, reproducibility, and integer-only runtime boundary checks. The maintainer also approved treating wall time and peak process RSS as **report-only** pending controlled hardware-specific benchmarks, with Raspberry Pi 5/AArch64 a later platform priority.

Issue [#15](https://github.com/philsupertramp/integers/issues/15) has fulfilled the **scientific measurement and criteria-definition milestones**. Integration of its candidate changes through [PR #34](https://github.com/philsupertramp/integers/pull/34) into `big-refactor` still requires PR review and a separate merge action. ADR-004 approval does **not** waive #26 integer-runtime audit, #16 dtype precision, #19 license/API policy, or PR #9's independent review/merge gates.

These criteria are *retrospectively informed by the existing MNIST test*. For future research optimized against that already-viewed benchmark, independent new held-out data or additional workloads are required for a fresh unbiased generalization claim.
