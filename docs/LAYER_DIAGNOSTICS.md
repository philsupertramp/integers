# Per-layer diagnostic experiment — issue #37

This work builds on [draft PR #58](https://github.com/philsupertramp/integers/pull/58)
and the independently reproduced deeper MNIST failures in [#38](https://github.com/philsupertramp/integers/issues/38).
It intentionally does **not** modify the model topology, initialization,
gradient clipping, rounding, SGD/momentum, sample order, validation data or
official-test-set boundary.

## Protocol and instrumentation scope

`--trace-layers` is opt-in and only accepted for an experimental `cnn4`,
`cnn8`, `cnn12`, `cnn16` or `cnn20` under `--validation-only`.
At the **first training minibatch** of epochs 1, 5, 10 and the final epoch,
capture immediately after the forward pass, immediately before the optimizer
update and immediately after it. Sampling frequency is fixed and bounded;
no full tensors are emitted to reports. A zero-length `layer_diagnostics`
field means tracing is off, not that there were no numerical events.

Every trainable Conv2D and Linear layer is identified by its forward index
and kind. The **raw integer** training probe reads dyadic mantissas/exponents,
min/max nonzero gradient exponent, maximum absolute gradient mantissa, parameter
and exact-zero gradient counts. `forward_zero_count` is the number of raw-zero
cached outputs in the sampled minibatch. `forward_saturated_count` counts
output requantization clip flags generated by normal forward arithmetic. Both
denominators are `forward_count` at this *sampled batch only*. `changed_parameters`
counts exact dyadic differences across the ordinary optimizer step;
`unchanged_parameters` is its complement, including legitimate zero
gradients, sub-unit updates lost to rounding, and other possible causes.
It is **not** a measured stochastic-round-to-zero count, which remains
`quantized_to_zero_updates: null` instead of making an invented attribution.

The **independent FP32** sample reads the corresponding reference model's
accumulated float gradients, zero/nonfinite counts, absolute gradient
maximum, parameter values and exact updates, but has no integer clipping
flags. Its missing clip metrics are therefore null, not zero.
The two processes run independently; no float computation is introduced
into the integer model forward/backward/update code.

Every diagnostics-enabled plan freezes its option under `diagnostics` in the
canonical checksum envelope and requires the matching report schema, layer
count (depth plus two dense layers), epoch set and gradient/update denominators.
Old plans and old archived reports remain valid without this option.

The integration invariance test runs both backends and depths 16/20 with the
same seed under trace-on and trace-off, asserting identical per-epoch learning
outcomes and confusion matrices. CI records timing/RSS for both modes;
those metrics describe optional tracing overhead on a *small smoke workload*
and are not stable hardware performance claims. The requirement is zero
numerical effect, not zero measurement overhead.

## Frozen 20-epoch control

Use the same MNIST development split, 8,192 training examples, 1,042 validation,
batch size 32, lr shift 7, He-v2 weights, no official test data.
Compare the two previously reproduced failures: depth 16/seed 4242
and depth 20/seed 4242. One independent integer and one independent FP32
process per combination, **20 epochs**, and opt-in layer tracing.
This is a fresh disclosed budget and not directly interchangeable with the
old ten-epoch gates. No auto-tuning or architecture tweaks are permitted.
Interpret early-vs-late layer gradient zero rates, update counts and saturation
alongside the independent FP32 learning curves.

A new report's `layer_diagnostics` schema is 1. Sampling only the first
minibatch is a limited observation; it cannot establish full epoch-wide
statistics, the exact prequantized gradient, or per-operation stochastic
rounding rates. Full arithmetic event counters remain future scope of #37.
